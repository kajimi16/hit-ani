hit-ani

基于 Bangumi 数据的校内动漫平台 —— 找番、追番、看番一站式，并带校内弹幕与评论影评。

Next.js 15 TypeScript PostgreSQL + Prisma 自建弹幕服务 校内自部署

它解决什么问题

Bangumi 提供条目、章节、评分与检索，是很好的「动漫维基」—— 但它只允许你写入自己收藏下的那一条短评，读不到别人的评论， 更没有任何弹幕接口（旧版评论接口已下线）。

也就是说，公共平台上「一起看、一起聊」这件事是没有的。 本项目补的正是这一层：校内可见的弹幕、评论与影评。

核心功能

  • 找番 —— 关键词 / 标签 / 评分 / 播出日期检索，新番时间表
  • 追番 —— 五种收藏状态（想看 / 在看 / 看过 / 搁置 / 抛弃），单集进度标记
  • Bangumi 账号绑定 —— 一键导入全部收藏、评分与观看进度，并支持回写
  • 校内弹幕 —— 自建弹幕服务：按集分房间、WebSocket 实时广播、时间轴与轨道渲染
  • 只看本校 —— 按学校维度筛选弹幕 / 评论 / 影评（索引命中，非事后过滤）
  • 评论与影评 —— 短评 / 长评 + 评分，同样支持校内筛选
  • 外部弹幕源 —— 可接入公共弹幕网络，让新平台冷启动时不至于空屏
  • 媒体服务器播放 —— 连接你自己的 Jellyfin / Emby， 视频由你的服务器直连播放器、叠加校内弹幕，不经过本平台

架构上的两个刻意取舍

  • 弹幕网关必须独立部署。 WebSocket 是长连接常驻进程，Serverless 函数有时限且无持久连接 —— 因此它是整个项目里唯一无法与 Next.js 合并的部分。
  • 播放不做服务端代理。 视频字节由用户浏览器直连媒体服务器或来源站 CDN，平台只做索引与元数据。 这既避免了带宽成本，也让平台停留在「播放器」而非「内容分发方」的位置。

合规边界

  • 本项目不托管任何视频内容，也不提供种子、不做种。
  • 条目与章节元数据来自 Bangumi， 遵循其 User-Agent 要求与使用条款。
  • 弹幕与评论属于用户生成内容，部署方需自行配置内容过滤与举报处理。
  • 资源源由部署方自行选择并承担相应责任，代码库不收录任何站点清单。

本地运行

# 1. 依赖与环境
npm install
cp .env.example .env      # 填 DATABASE_URL、SESSION_SECRET

# 2. 数据库
npm run db:push && npm run db:seed

# 3. 两个进程（弹幕网关必须独立常驻）
npm run dev        # http://localhost:3100
npm run gateway    # ws://localhost:3102

db:seed 会写入演示数据（两所学校、一个测试条目与几条弹幕）， 用于本地验证「只看本校」的筛选隔离。演示账号密码见 prisma/seed.ts —— 仅供本地开发，部署时请勿使用。

验证

npm run typecheck       # 类型检查
npm test                # 纯逻辑单测
npm run smoke           # 端到端冒烟（需 dev + gateway 已启动）
npm run bgm:check       # Bangumi 客户端联调（只读）
